## 2. The defect: Method X was visible to the judge and forbidden to the engine

The instrument displayed `methodX_transposase` and `methodX_integrase` feature tracks. Method X is
the profile-based annotation path **under test**. The frozen ground-truth engine
(`NMV1_RULE_ENGINE_FROZEN.json`, `ed5db383bb0afe1a1a8433886d6666fe72c324975de99c6763a37824d51c2bee`)
is defined **exclusively** on the two independent structural methods, Y and Z; rule E — the
quiescent state — is by construction a statement about Y and Z alone.

The adjudicator was therefore shown evidence that the engine was structurally prohibited from
using, and asked to agree with it.

### 2.1 The contamination is deterministic, not probabilistic

Among the **47** cases the engine labelled QUIESCENT:

| Method X marker displayed | cases | adjudicator called QUIESCENT |
|---|---:|---:|
| present | 38 | **0 of 38** |
| absent | 9 | **9 of 9** |

A perfect two-way separation. The adjudicator's call on the quiescent stratum was determined by a
field that carried no weight in the label being compared against. This is not noise around a true
disagreement rate — it is the instrument selecting the answer.

### 2.2 What this does and does not license

- It **does** establish that the R3 instrument cannot measure engine validity, because a variable
  outside the engine's definition fully explains the disagreement in the state that drove the FAIL.
- It **does not** establish that the engine is correct. The corrected audit has not been scored.
- It **does not** convert the FAIL into a pass, and no result may be quoted as if it did.

### 4.1 A structural limitation, recorded before the draw

Stated in the frozen protocol under `STRUCTURAL_LIMITATION_STATED_BEFORE_DRAWING`, before any case
was selected:

> The unused population contains **zero NON_EVALUABLE blocks and zero integron-exclusive (rule C)
> blocks.**

Cause: the frozen rules routed all 114 indeterminate blocks and all 8 rule-C blocks to *mandatory*
adjudication, so every one of them was already delivered in the V1/V2 packages. The unused pool is
A 106, B 157, C 0, D 1, E 316.

**Consequence, stated plainly: NM-V1C can validate the MOBILE versus QUIESCENT discrimination
only. It cannot validate the NON_EVALUABLE state, and it cannot produce an integron-specific
estimate.** The frame was not extended because sampling beyond the frozen 1,283 blocks would
require running ISEScan and IntegronFinder on new sequence — a larger deviation than the stated
limitation.

The adjudicator may still choose NON_EVALUABLE, with a required reason code; such a call counts as
a disagreement in the primary metric and is additionally reported separately by reason code.

## 5. The partial-element threshold is deliberately NOT changed

Of the partial-only cases in the failed audit, **19 of 20 were called MOBILE** by the adjudicator
while the engine returns F3 (indeterminate). This is a substantive scientific observation.

It is recorded here as a **developmental finding for a future revised classifier and is not acted
on now.** Revising F3 in light of a failed audit would convert validation into model development:
the threshold would have been tuned on the same expert calls used to judge it.

Any revised classifier receives a **new version number and a separate, untouched holdout**, drawn
only after the corrected validation of the *original* engine has been completed and reported. Note
that NM-V1C, by §4.1, cannot itself test this question — the NON_EVALUABLE boundary is exactly the
region it cannot sample.

## 6. Instrument defect found in the R1 build, corrected before delivery

The first NM-V1C application build (`NMV1C_ADJUDICATION_APP.html`,
`33dd3b0dcbda6ce8bd6620654f780de2dee83ccb8a08afb4b6ed6bf03bbefa01`) passed all 37 static blinding
and integrity checks, then **failed a functional test**: it initialised its decision store with an
unguarded `localStorage` read. Where a browser denies storage, that read throws, the `dec` binding
is left in the temporal dead zone, the initial `render()` throws, and **the page displays nothing
at all.**

Observed directly: `SecurityError: … Storage is disabled …` → `ReferenceError: Cannot access 'dec'
before initialization` → zero rendered cases. Storage denial occurs for opaque origins and
whenever a browser is configured to block site data for local files.

Corrected in build **R2**: storage reads and writes are wrapped and never fatal; the initial render
is guarded; a visible banner reports lost autosave; and progress can be restored from an exported
JSON file, so a storage-less browser remains fully usable for all 120 cases.

The defective R1 build **is retained unmodified**, alongside its manifest, as the record of the
defect. The regenerated key is **byte-identical** to the sealed R1 key
(`40e142e27978631da9ec437b9cdd7aeb8c5fda52bdecbbcda5f2fa2db8501efe`), which proves the draw,
tokens and weights are unchanged: only the application code differs.
